# Admin Migration Map (read side, phase 6A)

Every **read** query of the current admin frontend, and the new admin API endpoint that serves the same data from the self-hosted PostgreSQL.

- **Source of truth**: `src/routes/admin/*.tsx`, `src/routes/admin.tsx`, `src/components/admin/*`, `src/hooks/useAdminAuth.ts`.
- The frontend is **not** migrated yet: it still calls Supabase. Write operations follow in phase 6B.

All endpoints require an Auth0 access token with `admin:access` (see `docs/ADMIN-API.md`).

## Write queries (phase 6B, for reference only)

`bookings` insert/update/delete (agenda, reservaties), `booking_services` insert, `services` insert/update/delete plus automatic `vehicle_type_services` rows, `package_services` replace, `vehicle_types` insert/update/delete plus rows, `vehicle_type_services` updates, `blocked_periods` insert/delete, `site_settings` update, `gallery_items` insert/update/delete plus storage uploads. **None of these are implemented in phase 6A.**

## Behavioural differences (deliberate, documented)

| Topic                   | Current frontend                              | New API                                                                                                           |
| ----------------------- | --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Reservations list       | Loads **all** bookings                        | Server-side pagination (default 50, max 100); the same order plus `id` as tiebreak                                |
| Dashboard aggregates    | Computed in the browser from all week rows    | `COUNT`, `SUM` and `GROUP BY` in PostgreSQL; money summed as exact `numeric`                                      |
| "Today" and "this week" | Browser time zone                             | Europe/Brussels                                                                                                   |
| Agenda range            | Bookings whose **start date** is in the range | Bookings whose `[start_at, end_at)` **overlaps** the range, so multi-day bookings also appear on their later days |
| End time                | `end_time` text (can be `"25:00"`)            | `end_at` (ISO) plus `pickup_date`/`pickup_time` (local)                                                           |
| Cancel token            | `select *` returned it to the admin browser   | **Never** returned                                                                                                |
| Settings missing        | The admin page stayed on "Laden..."           | 500 `SETTINGS_NOT_CONFIGURED` (no invented defaults)                                                              |
