# Admin Write Migration Map (phase 6B)

Every **write** operation of the current admin frontend (source of truth: `src/routes/admin/*.tsx`), and the admin API endpoint that replaces it.

- The frontend is **not** migrated in this phase: it still writes to Supabase.
- All endpoints require an Auth0 access token with `admin:access` (`docs/ADMIN-API.md`).

## 2. Atomicity matrix

| Operation                             | Tables                                                                                                                            | Transaction required?                        | Concurrency                                                                                    | Notes                                                                      |
| ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Booking create                        | `bookings`, `booking_services`                                                                                                    | **Yes**                                      | Overlap pre-check + exclusion constraint `bookings_no_overlap_excl` (23P01 → 409)              | Shared engine with the public booking API                                  |
| Booking update                        | `bookings` (+ `booking_services` when services change)                                                                            | **Yes**                                      | `SELECT … FOR UPDATE` on the booking; overlap check **excluding itself**; exclusion constraint | Re-priced only when services or the vehicle type change                    |
| Booking delete                        | `bookings` (+ `booking_services` CASCADE)                                                                                         | No (one statement; the cascade is atomic)    | —                                                                                              | 404 when unknown                                                           |
| Service create                        | `services`, `vehicle_type_services`                                                                                               | **Yes**                                      | —                                                                                              | UI defaults: price 0, duration 60, for all vehicle types                   |
| Service update                        | `services`                                                                                                                        | No (one statement)                           | —                                                                                              | Package contents are separate                                              |
| Service delete                        | `services` (+ CASCADE `vehicle_type_services`, `package_services`; SET NULL `booking_services.service_id`, `bookings.service_id`) | No (one statement; FK actions are atomic)    | —                                                                                              | Snapshots are kept                                                         |
| Package content update                | `package_services`                                                                                                                | **Yes**                                      | —                                                                                              | Delete and insert together                                                 |
| Vehicle type create                   | `vehicle_types`, `vehicle_type_services`                                                                                          | **Yes**                                      | UNIQUE `slug` (23505 → 409)                                                                    | UI defaults: price 30, duration 60, for active and bookable services       |
| Vehicle type update                   | `vehicle_types`                                                                                                                   | No (one statement)                           | UNIQUE `slug` (→ 409)                                                                          | —                                                                          |
| Vehicle type delete                   | `vehicle_types` (+ CASCADE `vehicle_type_services`)                                                                               | No (one statement)                           | FK RESTRICT from `bookings` (23503 → 409 `RESOURCE_IN_USE`)                                    | —                                                                          |
| Pricing matrix update                 | `vehicle_type_services`                                                                                                           | **Yes**                                      | —                                                                                              | One upsert per row inside the transaction; any failure rolls all rows back |
| Blocked period create                 | `blocked_periods`                                                                                                                 | No (one statement)                           | —                                                                                              | DB CHECKs are the last line of defence                                     |
| Blocked period delete                 | `blocked_periods`                                                                                                                 | No (one statement)                           | —                                                                                              | —                                                                          |
| Settings update                       | `site_settings`                                                                                                                   | Yes (lock, read, merge and validate, update) | `SELECT … FOR UPDATE`                                                                          | One row, updated in place                                                  |
| Gallery metadata create/update/delete | `gallery_items`                                                                                                                   | No (one statement each)                      | —                                                                                              | No storage in this phase                                                   |

**Transaction style**: every multi-statement mutation calls Drizzle's `db.transaction(async (tx) => …)` **directly in its service function**, so the transaction boundaries are visible in the code. There is no generic transaction abstraction. Any error thrown inside the callback rolls back the whole transaction.
